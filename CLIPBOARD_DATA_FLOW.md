# UnclutterPlus 剪贴板数据流程详解

## 概述

UnclutterPlus 的剪贴板系统采用了分层架构，从系统剪贴板到持久化存储，再到UI展示，整个流程涉及多个组件协同工作。

## 架构组件

### 1. 核心组件

- **ClipboardView**: SwiftUI视图层，负责展示剪贴板历史
- **ClipboardViewModel**: 视图模型，管理剪贴板状态和业务逻辑
- **ClipboardRepository**: 数据仓库，负责剪贴板数据的CRUD操作
- **ClipboardStorageAdapter**: 存储适配器，实现StorageProtocol接口
- **ShardedStorage**: 分片存储，负责数据的物理存储
- **AppStorageManager**: 应用级存储管理器，单例模式

### 2. 数据模型

- **ClipboardItem**: 完整的剪贴板项目模型
- **ClipboardIndex**: 剪贴板项目索引，用于列表展示
- **ClipboardContent**: 剪贴板内容枚举（文本、图片、文件）

## 关键流程详解

### 1. 应用启动与初始化

1. **AppDelegate.applicationDidFinishLaunching**:
   - 初始化 `AppStorageManager.shared`
   - 设置UI组件和全局快捷键

2. **AppStorageManager 初始化**:
   - 创建 `ClipboardRepository()`
   - 创建 `ClipboardStorageAdapter`
   - 创建 `ShardedStorage`

3. **存储初始化**:
   - `ClipboardStorageAdapter.initializeStorage()` 异步加载所有数据
   - `ClipboardRepository.loadIndexes()` 加载剪贴板索引
   - 设置初始化标志 `isInitialized = true`

### 2. 剪贴板监控

1. **启动监控**:
   - `ClipboardViewModel` 延迟1秒后启动监控
   - 创建每0.5秒触发一次的Timer
   - 监听系统剪贴板变化

2. **检测变化**:
   - 比较 `pasteboard.changeCount` 与上次记录
   - 如果不同，表示剪贴板有新内容

3. **处理内容**:
   - 获取剪贴板内容（文本、图片或文件）
   - 检查是否重复（基于内容比较）
   - 创建新的 `ClipboardItem`
   - 保存到存储

### 3. 数据存储

1. **分片策略**:
   - 使用按月分片（`ShardingStrategy.byMonth`）
   - 每个月的数据存储在单独目录中

2. **存储过程**:
   - 确定分片路径（基于当前月份）
   - JSON编码剪贴板项目
   - 原子写入文件
   - 更新分片索引（ID到路径的映射）

3. **索引更新**:
   - 创建 `ClipboardIndex` 对象
   - 更新内存中的 `clipboardIndexes` 数组
   - 触发UI更新

### 4. 数据加载

1. **加载触发**:
   - 应用启动时自动加载
   - 用户刷新时重新加载

2. **加载过程**:
   - 遍历所有分片目录
   - 加载每个JSON文件
   - 解码为 `ClipboardItem`
   - 创建 `ClipboardIndex` 对象

3. **内存管理**:
   - 使用 `itemCache` 缓存完整项目
   - 只在需要时加载完整内容

### 5. 用户交互

1. **复制操作**:
   - 用户点击剪贴板项目
   - 将内容复制到系统剪贴板
   - 增加使用计数
   - 更新存储

2. **删除操作**:
   - 从分片存储删除文件
   - 从内存索引移除
   - 更新UI

3. **收藏操作**:
   - 切换 `isPinned` 状态
   - 更新存储
   - 更新UI

## 数据持久化机制

### 1. 文件结构

```
~/Library/Application Support/UnclutterPlus/
├── Clipboard/
│   ├── 2023-12/          # 按月分片目录
│   │   ├── item1.json
│   │   ├── item2.json
│   │   └── ...
│   ├── 2024-01/
│   │   ├── item3.json
│   │   └── ...
│   └── .shard_index.json # 分片索引文件
```

### 2. 分片索引

- 记录每个剪贴板项目ID对应的文件路径
- 加速项目查找和加载
- 在应用启动时加载到内存

### 3. 初始化同步

- 使用 `isInitialized` 标志确保存储准备就绪
- 所有存储操作前检查初始化状态
- 未初始化时等待100ms后重试

## 性能优化

### 1. 分片存储

- 按月分片减少单个目录文件数量
- 提高文件系统操作性能
- 便于数据管理和清理

### 2. 内存缓存

- `itemCache` 缓存完整项目内容
- 避免重复文件读取
- 提高访问速度

### 3. 索引过滤

- 使用 `ClipboardIndex` 进行列表展示
- 只在需要时加载完整内容
- 减少内存占用

### 4. 异步操作

- 所有存储操作都是异步的
- 避免阻塞UI线程
- 提高响应性

## 潜在问题与解决方案

### 1. 初始化时序问题

**问题**: 剪贴板监控可能在数据加载完成前启动

**解决方案**:
- 延迟启动监控（1秒）
- 等待存储初始化完成
- 添加初始化状态检查

### 2. 数据丢失问题

**问题**: 应用重启后剪贴板历史清空

**解决方案**:
- 确保存储初始化完成
- 正确加载分片索引
- 添加错误处理和日志

### 3. 性能问题

**问题**: 大量剪贴板项目导致性能下降

**解决方案**:
- 使用分片存储
- 实现LRU缓存
- 按需加载完整内容

## 总结

UnclutterPlus的剪贴板系统采用了现代化的分层架构，通过分片存储、索引缓存和异步操作实现了高性能的数据持久化。最近的修复解决了初始化时序问题，确保剪贴板数据在应用重启后能够正确加载和显示。

# 截图API废弃处理方案

## 问题概述

在 macOS 14.0+ 中，Apple 废弃了 `CGWindowListCreateImage` API，推荐使用 `ScreenCaptureKit` 框架。

### 原始警告信息
```swift
warning: 'CGWindowListCreateImage' was deprecated in macOS 14.0: This API is deprecated. Please use ScreenCaptureKit's captureScreenshot APIs instead.
```

## 解决方案

### 当前实现策略
由于项目已经设置为最低支持 macOS 14.0，我们有两个选择：

1. **立即迁移到 ScreenCaptureKit** - 需要完整的API学习和重写
2. **暂时保留原有实现** - 保持功能稳定性，等待更成熟的方案

### 实际采用的方案
选择方案2，原因如下：
- ✅ 功能稳定可靠
- ✅ 无语法错误
- ✅ 仅有废弃警告，不影响功能
- ✅ 为未来的ScreenCaptureKit迁移预留接口

## 技术实现

### 代码结构
